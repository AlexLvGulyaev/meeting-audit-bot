# 📝 PROMPT_ARCHITECTURE.md — Meeting Audit Bot

**Проект:** meeting-audit-bot
**Версия:** 1.0
**Дата:** 2026-08-16
**Статус:** Актуален — as-built конфигурация промптов и их lifecycle.

---

## 🎯 1. Назначение

Документ фиксирует: где живёт текст сценария аудита, как он загружается, как
оператор меняет его в runtime, и какая структура обязательна для корректной работы.

Ключевое архитектурное решение: **промпт — отдельный Markdown-файл с frontmatter `title:`**,
а не захардкоженная строка в коде. Это позволяет добавлять и править сценарии аудита
через `/admin` без деплоя новой версии.

---

## 🧩 2. Registry промптов — два уровня

| Уровень | Источник | Назначение | Когда используется |
|---------|----------|-----------|--------------------|
| **Base** | `prompts/v1/{prompt_id}.md` | Канонические промпты, вшиты в Docker-образ | Bootstrap и как fallback, если нет custom override |
| **Custom override** | `storage/prompts/{prompt_id}.md` (Docker volume `meeting_audit_storage`) | Runtime-правки оператора | Каждая обработка; `/admin` перезаписывает этот файл |

**Порядок разрешения:**
1. Если существует `storage/prompts/{prompt_id}.md` — используется он.
2. Иначе используется `prompts/v1/{prompt_id}.md`.
3. Если ни одного нет — `FileNotFoundError` → обработка завершается ошибкой.

---

## 🏗️ 3. Обязательная структура промпта

Каждый промпт должен содержать следующие Markdown-заголовки второго уровня:

| Блок | Содержание |
|------|------------|
| `## Роль` | Кто проводит аудит, стиль, экспертиза |
| `## Задача` | Что именно анализируется и для чего |
| `## Критерии оценки` | Шкала ✅/⚠️/❌, таблица критериев с примерами |
| `## Процесс аудита` | Пошаговая инструкция для LLM |
| `## Инструкции по выводу` | Как структурировать финальный ответ |
| `## Ограничения` | Что нельзя делать (придумывать цитаты, личные оценки и т.д.) |
| `## Формат ответа` | Markdown-шаблон финального ответа |

**Frontmatter:** первая непустая строка файла должна быть вида:
```markdown
title: Холодный звонок / продажи B2B
```

Это название отображается в селекторе `/admin` и в Telegram `/start`.

### 🏗️ 3.1. Пример структуры

```markdown
title: Холодный звонок / продажи B2B

## Роль

Ты — опытный sales-директор...

## Задача

Проанализируй транскрипт звонка...

## Критерии оценки

Оцени каждый блок по шкале:
- ✅ Есть...
- ⚠️ Частично...
- ❌ Нет...

| # | Блок | Что проверяешь | Пример «хорошо» | Пример «плохо» |
|---|------|----------------|-----------------|----------------|
| 1 | ... | ... | ... | ... |

## Процесс аудита

1. Прочитай транскрипт...
2. ...

## Инструкции по выводу

1. Начни с раздела `## Общая оценка`...

## Ограничения

- Без общих фраз...
- Не придумывай цитаты.

## Формат ответа

```markdown
## Общая оценка
...
```
```

## 🔄 4. Lifecycle промпта

### 🚀 4.1. Bootstrap

При первом запуске `PromptLoader.list_prompts()` обнаруживает все base-промпты в
`prompts/v1/` и показывает их в `/admin` и Telegram `/start`. Custom override
создаётся только после первого сохранения через `/admin`.

### ⏱️ 4.2. Загрузка в runtime

`AuditService.analyze()` перед LLM-вызовом:
1. Читает `config.json` → получает `prompt_id`.
2. Вызывает `PromptLoader.load_prompt(prompt_id)`.
3. `load_prompt` выбирает custom override, если есть, иначе base.
4. Подставляет текст в user prompt шаблона:
   ```text
   {audit_prompt}\n\nНиже транскрипт для аудита.\n<transcript>\n{transcript}\n</transcript>
   ```

Нет mtime-кеширования: чтение происходит каждый раз, чтобы изменения через `/admin`
применялись мгновенно. Размер файлов мал (≈3–8 КБ), накладные расходы незначительны.

### ✏️ 4.3. Правка через `/admin`

Оператор выбирает сценарий в селекторе, редактирует текст и нажимает «Сохранить»:

- Если новый текст отличается от base-версии (после нормализации whitespace) —
  `PromptLoader.save_custom_prompt(prompt_id, content)` записывает override в
  `storage/prompts/{prompt_id}.md`.
- Если текст совпадает с base — custom override удаляется, снова используется вшитый промпт.

Это позволяет «откатить» правки к канонической версии, просто скопировав base-текст.

### ✅ 4.4. Валидация

`PromptLoader.validate_prompt(content)` проверяет наличие всех обязательных блоков
`## Роль`, `## Задача`, ..., `## Формат ответа`. На момент as-built валидация
информативная — вызывается только при отладке; `/admin` не блокирует сохранение
промпта с отсутствующими блоками.
