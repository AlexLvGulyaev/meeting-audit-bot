# 📋 SPEC — Meeting Audit Bot

**Проект:** meeting-audit-bot
**Версия:** 1.0
**Дата:** 2026-08-16
**Статус:** Frozen baseline

---

## 1. Цель проекта

Создать AI-ассистента для аудита аудио- и видеовстреч. Пользователь отправляет запись в Telegram; бот транскрибирует речь через AssemblyAI с разделением по спикерам и проводит структурированный аудит диалога по заданным критериям через LLM. Администратор управляет сценариями аудита и провайдерами LLM через веб-панель `/admin`.

---

## 2. Роли

| Роль | Кто это | Что делает |
|------|---------|-----------|
| **Пользователь Telegram** | Сотрудник/менеджер, отправляющий запись | Отправляет аудио/видео; получает аудит |
| **Администратор** | Владелец/инженер с полным токеном | Меняет сценарий аудита, провайдера, модель; видит сессии и аудит лог |
| **Демо-наблюдатель** | С read-only токеном | Смотрит `/admin`, но не может менять настройки |
| **Система** | FastAPI + Telegram bot + STT + LLM | Скачивает, транскрибирует, аудитит, сохраняет, уведомляет |

## 3. Функциональные требования

### F-REQ-01. Приём файлов в Telegram

- Telegram-бот принимает видео и аудио файлы.
- Поддерживаемые форматы: mp3, mp4, ogg, wav, m4a и другие, распознаваемые Telegram.
- Бот скачивает файл в `storage/uploads/`.
- Пользователю показывается прогресс-сообщение.

### F-REQ-02. Транскрибация

- Используется AssemblyAI API.
- Транскрипт формируется с разделением по спикерам (`Speaker A`, `Speaker B`).
- Длинные файлы обрабатываются в фоне; результат сохраняется в `storage/transcripts/`.

### F-REQ-03. Аудит диалога

- Активный промпт выбирается через runtime-конфиг `/admin`.
- Промпт содержит блоки: `Роль`, `Задача`, `Критерии оценки`, `Процесс аудита`, `Инструкции по выводу`, `Ограничения`, `Формат ответа`.
- LLM провайдер выбирается через `/admin`: OpenAI, GigaChat.
- Поддерживается fallback-провайдер при недоступности активного.

### F-REQ-04. Сохранение результатов

- Исходный файл — `storage/uploads/`.
- Транскрипт — `storage/transcripts/`.
- Аудит — `storage/audits/`.
- Метаданные обработки — `video_audits` в PostgreSQL.

### F-REQ-05. Execution tracing

- Каждая обработка файла = `execution_session`.
- Шаги: `download`, `transcribe`, `audit`, `notify`.
- Каждый шаг фиксирует статус и метаданные.

### F-REQ-06. Security audit

- Таблица `admin_audit_log` фиксирует: вход/выход в `/admin`, смену runtime-config, создание/редактирование промптов, RBAC-отказ, превышение Telegram-квоты.
- Поля: actor, user_id, user_name, user_role, ip_address, action, resource_type, resource_id, JSONB details.

### F-REQ-07. Web-админка

- `/admin` — cookie-based auth.
- `/admin/login/demo` — одно-кликовый демо-вход (read-only).
- `/admin/executions` — консоль «Сессии»: список обработок с детализацией шагов, транскрипта и аудита.
- `/admin/audit` — консоль «Аудит»: security/админ события.
- Dashboard показывает статус провайдеров, активный промпт, метрики.

### F-REQ-08. Ограничения и безопасность

- Квота 5 успешных обработок в сутки на обычного пользователя.
- `ADMIN_USER_ID` не учитывается в квоте.
- Секреты только в `.env`.
- Demo-токен не позволяет менять настройки (backend guard).

### F-REQ-09. Observability

- `/health` — проверка приложения и БД.
- stdout-логи.
- `execution_sessions`/`execution_steps` + `admin_audit_log`.

## 5. Бизнес-правила

- Один аудио/видеофайл = одна `execution_session`.
- Смена активного промпта в `/admin` применяется к следующей обработке без рестарта.
- Активный LLM → fallback LLM → ошибка, если оба недоступны.
- Пользователь без `ADMIN_USER_ID` ограничен 5 успешными обработками за сутки.
- Промпты с одинаковым `id` в `storage/prompts/` перекрывают базовые в `prompts/v1/`.

---

## 6. Границы проекта

- AssemblyAI — единственный STT-провайдер в v1.0.
- Telegram polling — основной UI; webhook не реализуется в v1.0.
- Версионирование промптов не реализуется в v1.0.
- Аудит только текстовый; голосовые ответы не генерируются.
