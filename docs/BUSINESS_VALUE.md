# 💼 BUSINESS_VALUE.md — Meeting Audit Bot

**Проект:** meeting-audit-bot
**Дата:** 2026-08-16
**Статус:** Портфельный актив — готовый шаблон «STT + LLM-аудит входящего контента через мессенджер».

> 📌 **Позиционирование:** проект демонстрирует не только «аудит звонков», но и **переиспользуемый паттерн** — конвейер «получить медиа из мессенджера → транскрибировать с диаризацией → провести структурированный аудит по критериям → вернуть результат в тот же канал». Звонки и встречи — лишь один из примеров применения (см. §6).

---

## 🎯 1. Проблема

Команды продаж, CX и обучения регулярно разбирают записи звонков и встреч. Без автоматизации:

### 🏢 1.1. Со стороны бизнеса-заказчика (кому внедряют)

| Проблема | Последствие |
|----------|-------------|
| Разбор звонков делается вручную руководителем | 30–60 мин на один звонок → руководитель успевает разобрать лишь небольшую выборку |
| Нет единой шкалы оценки | Один менеджер оценивает жёстко, другой — мягко, обратная связь непредсказуема |
| Новые менеджеры не получают быстрой обратной связи | Ошибки закрепляются неделями, пока руководитель не найдёт время на разбор |
| Нет 24/7 разбора | Записи, сделанные вечером или в выходные, лежат до следующего рабочего дня |
| Сложно отслеживать динамику по команде | Разбросанные заметки, нет централизованной истории аудитов |

### 🧩 1.2. Со стороны интегратора (кто внедряет)

| Проблема | Последствие |
|----------|-------------|
| Нет готовой заготовки «Telegram-бот + STT + LLM-аудит» | Каждую автоматизацию аудита собирают с нуля |
| Один захардкоженный провайдер | Сбой или изменение API провайдера останавливает систему |
| Промпт в коде | Любая правка критериев аудита = деплой новой версии |
| Нет observability | Не видно, где упал конвейер: скачивание, транскрибация или LLM |
| Нет контроля за расходами на AI-вызовы | Без лимитов и failover растут непредвиденные затраты на STT/LLM при росте нагрузки |

---

## 💡 2. Решение

Telegram-бот, который принимает аудио/видео, транскрибирует речь через AssemblyAI с разделением по спикерам (`speaker_labels`) и проводит структурированный аудит по выбранному сценарию через LLM. Результат возвращается в тот же чат. Руководитель видит все обработки в админке `/admin` с execution-трейсами и security audit log.

Архитектурные решения, создающие ценность:

- **Мультипровайдерность + fallback.** OpenAI / GigaChat через единую абстракцию `LLMProvider`; цепочка active → fallback → статический fallback. Провайдер меняется в runtime через `/admin` без рестарта. Технически — [🏗️ `ARCHITECTURE.md` §5](ARCHITECTURE.md).
- **Prompt registry.** Базовые промпты в `prompts/v1/*.md` с human-readable `title:` frontmatter, custom override в `storage/prompts/*.md`. Оператор правит сценарий аудита через `/admin` без деплоя. Подробнее — [📝 `PROMPT_ARCHITECTURE.md`](PROMPT_ARCHITECTURE.md).
- **RBAC админки.** Cookie-based auth: полный токен оператора (мутации) + read-only токен (только просмотр). Backend guard на мутациях. См. [🛡️ `SECURITY_NOTES.md`](SECURITY_NOTES.md).
- **Execution tracing + аудит.** Каждая обработка разбивается на шаги (`download`, `transcribe`, `audit`, `persist`), сохраняется в PostgreSQL. Security audit log фиксирует действия администраторов.
- **Контроль расходов и отказоустойчивость.** Multi-provider fallback + runtime-переключение модели снижают риск непредвиденных затрат и простоев при сбоях провайдера.
- **Централизованная очистка Markdown.** LLM-иногда оборачивает ответ в ```markdown ... ```; `strip_markdown_fence` удаляет обёртку до рендера в Telegram и админке.

## 💰 3. Количественная бизнес-ценность

> 📌 Все показатели ниже — оценочные, для демонстрации порядка величин.

### ⏱️ 3.1. Для заказчика-внедрения: время и качество разбора звонка

| Показатель | Без автоматизации | С Meeting Audit Bot |
|------------|-------------------|---------------------|
| Время разбора одного звонка | 30–60 мин руководителя | 1–3 мин на загрузку + 30–120 с на обработку |
| Покрытие записей | Выборочное (10–20%) | 100% загруженных записей |
| Доступность разбора | Рабочие часы руководителя | 24/7 |
| Согласованность критериев | Зависит от руководителя | Один и тот же промпт для всех записей |
| Время обратной связи менеджеру | Часы–дни | Минуты |

### ⚡ 3.2. Для интегратора: ускорение внедрения

| Показатель | С нуля | От этой базы |
|------------|--------|--------------|
| Готовый конвейер «Telegram → STT → LLM-аудит → чат» | 1–2 недели | Настроить промпт + ключи |
| Multi-provider fallback | Своё решение | Готовая цепочка из коробки |
| Runtime-конфиг и prompt registry | Своё решение | Готовый механизм |
| Observability (execution trace + audit log) | Своё решение | Три контура из коробки |
| RBAC админки | Своё решение | Готовый паттерн (два токена, backend-guard) |

### 💵 3.3. Стоимость одной обработки (оценка)

| Статья | Стоимость на одну запись ~10 мин |
|--------|----------------------------------|
| AssemblyAI STT (`universal-3-5-pro`, speaker labels) | ~$0,01–0,02 |
| LLM-аудит (`gpt-4.1-mini`, ~2K токенов) | ~$0,003–0,005 |
| **Итого** | **~$0,02–0,03 за запись** |

Сравнение: ручной разбор руководителем стоимостью $30–60/час и 30 мин времени = **$15–30 за звонок**. Автоматизация снижает стоимость разбора на **2–3 порядка**.

## 🚀 4. Варианты применения паттерна

Тот же конвейер «мессенджер → медиа → STT → LLM-аудит → чат» применим к другим задачам:

| Сценарий | Что аудирует LLM | Канал доставки |
|----------|------------------|----------------|
| Аудит онбординг-встреч | Полнота передачи обязанностей, план первых шагов | Telegram + `/admin` |
| Аудит уроков/лекций | Структура, понятность, наличие примеров | Telegram + `/admin` |
| Аудит клиентских чатов (голосовые) | Соблюдение скрипта, работа с возражениями | Telegram/WhatsApp |
| Аудит службы поддержки | Эмпатия, точность ответа, эскалация | Telegram-бот |
