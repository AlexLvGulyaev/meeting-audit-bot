## 🔐 1. Доступ к админке

Операторская панель `/admin` защищена двумя токенами (демо-RBAC, см.
[🛡️ SECURITY_NOTES.md](SECURITY_NOTES.md) §2). Вход — два пути на странице логина:

1. **Полный доступ** — введите `ADMIN_TOKEN` в форму. Роль `admin`, cookie
   `meeting_audit_admin` (1 ч). Это единственная роль, допущенная к мутациям
   (`POST /admin/save`, `POST /admin/test-provider`).
2. **Демо-доступ (одно-кликовой)** — кнопка «Войти в демо-режим (только просмотр)».
   Сервер сам ставит cookie с `ADMIN_DEMO_TOKEN` — **токен не попадает в браузер**.
   Роль `demo-admin`, все поля формы disabled. Мутации → `403` на backend.

![Страница входа в /admin: форма полного токена и одно-кликовой демо-вход](screenshots/admin-login.png)

*Страница входа: полный токен или одно-кликовой демо-вход (токен не в браузере).*

> ⚠️ Если `ADMIN_DEMO_TOKEN` не задан в `.env` — кнопка демо-входа показывает
> «Демо-вход отключён». Для локальных тестов можно отключить auth, но **только локально**.

После входа — sidebar-лэйаут (домстиль AIP Dark) с тремя консолями:
**Конфигурация** (`/admin`), **📜 Сессии** (`/admin/executions`), **📋 Аудит** (`/admin/audit`).
Все панели чтения доступны и admin-, и demo-токеном.

## ⚙️ 2. Операторские параметры

Параметры, которые оператор меняет в `/admin` без рестарта. Они пишутся в
`storage/config.json` (shared volume) и `storage/prompts/{prompt_id}.md`;
Telegram-бот подхватывает их при следующей обработке.

| Параметр | Где в `/admin` | Что делает | Применение |
|----------|----------------|-----------|-----------|
| **Активный провайдер** | «Настройки LLM» | `openai` / `gigachat` — через кого генерируется аудит | Следующая обработка |
| **Fallback провайдер** | «Настройки LLM» | LLM-запас на случай сбоя активного | Следующая обработка |
| **OpenAI Base URL** | Карточка OpenAI | Для OpenAI-compatible endpoints | Следующая обработка |
| **Model** (per-провайдер) | Карточки провайдеров | `openai_model` / `gigachat_model` | Следующая обработка |
| **Temperature / Max tokens** | Карточки провайдеров | Per-провайдер | Следующая обработка |
| **Активный сценарий аудита** | Селектор промптов | Какой промпт использовать | Следующая обработка |
| **Текст сценария** | Текстовая область промпта | Правит критерии аудита | Следующая обработка (если сохранён custom override) |

![Dashboard /admin: статусы, селектор промпта, карточки провайдеров](screenshots/admin-dashboard.png)

*Dashboard: состояние системы, активный промпт и настройки провайдеров.*

![Открытый селектор активного промпта](screenshots/admin-change-prompt.png)

*Селектор показывает human-readable названия из `title:` frontmatter.*

> 🔒 **Секреты — не операторские параметры.** Ключи (`TELEGRAM_BOT_TOKEN`,
> `ASSEMBLYAI_API_KEY`, `OPENAI_API_KEY`, `GIGACHAT_AUTH_KEY`) и токены
> (`ADMIN_TOKEN`, `ADMIN_DEMO_TOKEN`) меняются **только в `.env`** и требуют
> пересборки. В `/admin` они не попадают и не перезаписываются.

## 🎛️ 3. Смена провайдера и модели без рестарта

1. Войдите полным токеном (сценарий §1). Откройте `/admin`.
2. В панели «Настройки LLM» выберите **Активный провайдер** и **Fallback провайдер**.
3. В карточках провайдеров задайте **Model**, **Temperature**, **Max tokens**.
   Для OpenAI при желании поменяйте **Base URL** (GigaChat — read-only из `.env`).
4. Нажмите **Сохранить** → редирект `?saved=1`.
5. Отправьте новое аудио/видео в Telegram. Бот подхватит новый `config.json` —
   **без рестарта контейнера**.

**Ожидаемый результат:** аудит сгенерирован через активный LLM. При сбое/недоступности
активного — сработает fallback LLM, затем статический fallback. Execution-трейс фиксирует
`provider` и `model`.

## 📝 4. Правка сценария аудита в runtime

Промпты живут в двух уровнях: базовые (`prompts/v1/*.md`, вшитые в образ) и custom
override (`storage/prompts/*.md`). Оператор видит объединённый registry с human-readable
названиями из `title:` frontmatter.

1. Войдите полным токеном. В `/admin` выберите сценарий в селекторе.
2. Текст промпта подгрузится в текстовую область.
3. Отредактируйте критерии или формат вывода.
4. Нажмите **Сохранить**.
   - Если текст отличается от base-версии — сохранится в `storage/prompts/{prompt_id}.md`.
   - Если текст совпадает с base — custom override удалится, используется вшитая версия.
5. Отправьте новое аудио/видео в Telegram — аудит пойдёт уже по обновлённому сценарию.

> 📌 Каждый промпт обязан содержать блоки: `## Роль`, `## Задача`,
> `## Критерии оценки`, `## Процесс аудита`, `## Инструкции по выводу`,
> `## Ограничения`, `## Формат ответа`. Подробнее —
> [📝 `PROMPT_ARCHITECTURE.md`](PROMPT_ARCHITECTURE.md).

## ✅ 5. «Проверить» — real-тест провайдера

В каждой карточке провайдера есть кнопка **Проверить**.

1. Нажмите **Проверить** на карточке провайдера.
2. Сайт делает real-вызов LLM (1 токен).
3. Появляется toast-уведомление: «✓ Проверка «openai»: готов, ~500мс» или сообщение об ошибке.

![Toast-результат real-теста провайдера](screenshots/admin-provider-test.png)

*«Проверить»: toast с результатом real-вызова.*

**Ключевое:** LLM-ключи живут **только в `.env` на контейнере** — через `/admin` их не видно.
Событие пишется в аудит (`admin.provider_test`).

## 👁️ 8. Демо-режим (только просмотр)

Войдите по `ADMIN_DEMO_TOKEN` через кнопку демо-входа.

- Поля формы disabled.
- Кнопки «Сохранить» и «Проверить» недоступны.
- Просмотр dashboard, сессий, аудита — доступен.
- Прямой `POST /admin/save` с demo-cookie отклоняется backend'ом (`403`).

![Демо-режим read-only](screenshots/admin-demo-readonly.png)

*Demo-сессия: формы disabled, мутации заблокированы на backend.*
